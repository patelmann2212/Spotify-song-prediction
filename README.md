# 🎵 Spotify Song Recommendation System

A robust, modular **Content-Based & Hybrid Recommendation System** written in Python using `pandas`, `numpy`, and `scikit-learn`. The system analyzes structural audio features (e.g., danceability, energy, tempo, acousticness), artist token distributions, and genre audio profiles to deliver deterministically ranked song recommendations.

---

## 🚀 Features

- **Leak-Free Preprocessing Pipeline**: The `MinMaxScaler` is fitted strictly on the training partition (`X_train`), ensuring zero data leakage into validation, test, or catalog evaluation.
- **Group-Aware Splitting**: Uses a composite grouping key (`base_title + "___" + normalized_artists`) with `GroupShuffleSplit` so logical tracks, remixes, live performances, and acoustic versions never leak across train, validation, and test splits.
- **Dual Catalog Architecture**: Clearly separates the **Searchable Recommendation Catalog** (`data/cleaned_spotify.csv`, containing all deduplicated tracks) from the **Evaluation Datasets** (`train.csv`, `validation.csv`, `test.csv`). Users can search any song in the catalog without being artificially constrained to an 80% train partition.
- **Deterministic Song Resolution**: A dedicated lookup engine (`src/song_lookup.py`) handles:
  - Exact normalized title matches
  - Optional artist filtering (e.g., `"Shape of You"` + `"Ed Sheeran"` vs `"Andrew Foy"`)
  - Intelligent popularity ranking for duplicate titles (e.g., preferring The Weeknd pop 91 over Kidz Bop pop 0 for `"Blinding Lights"`)
  - Stable tie-breaking via `track_id` (eliminating dataframe row-order dependence)
  - Safe error reporting for nonexistent songs (no silent misidentification)
- **Multi-Engine Recommendation Stack**:
  1. **Content-Based Filtering**: On-the-fly cosine similarity across 10 normalized audio dimensions.
  2. **Genre-Specific Recommender**: Restricts candidates to the query song's genre and ranks by acoustic similarity.
  3. **Artist Similarity Recommender**: Measures name and collaboration token overlap using TF-IDF.
  4. **Mood-Based Recommender**: Classifies songs into Party, Chill, Happy, and Sad using rule-based thresholds.
  5. **Weighted Hybrid Recommender**: Blends Audio (50%), Artist (20%), Genre Profile (20%), and Popularity (10%).

```text

       ↓
Basic Cleaning (Null handling & whitespace trimming)
       ↓
Deduplication (Highest popularity kept for identical (track_name, artists))

Group-Aware Train / Val / Test Split

       ↓

       ↓
Transform Splits:
  ├── X_train_scaled      = scaler.transform(X_train)
  ├── X_val_scaled        = scaler.transform(X_val)
  ├── X_test_scaled       = scaler.transform(X_test)

       ↓
Save Datasets & Models:
  ├── data/processed/train.csv, validation.csv, test.csv
  ├── data/cleaned_spotify.csv (Searchable Catalog)
  └── models/scaler.pkl (Fitted on train ONLY)
```

## 🎯 Song Resolution Strategy

Querying songs using simple title matching or arbitrary first matches (`matches.iloc[0]`) is dangerous because:
1. Different artists release songs with the same title (e.g., covers, separate compositions).
2. The same song exists in multiple versions (e.g., original vs. Kidz Bop).
3. Shuffled splits randomize row ordering.

### Lookup Resolution Rules (`src/song_lookup.py`):
- **Normalization**: Casing, leading/trailing whitespace, consecutive spaces, and basic punctuation are normalized for search without altering raw display text.
- **Title + Artist Supplied**: If an artist is provided, candidates are filtered to those matching the artist name (including sub-artist tokens in collaborations). Unrelated artists are never silently picked.
- **Song Only Supplied**: Matches are ranked by:
  1. Exact normalized title match (`_exact_title` descending)
  2. Track popularity descending (The Weeknd pop 91 > Kidz Bop pop 0 for *"Blinding Lights"*)
  3. Stable tie-breaker: `track_id` ascending
- **Missing Songs**: Nonexistent tracks return an explicit error rather than guessing a fallback track.

## ⚖️ Recommendation Catalog vs. Evaluation Data

In machine learning recommendation systems, training/evaluation data and the searchable catalog serve distinct purposes:
- **Evaluation Datasets (`train.csv`, `val.csv`, `test.csv`)**: Used to fit models, tune hyper-parameters, and evaluate generalizability with zero data leakage.
- **Searchable Recommendation Catalog (`cleaned_spotify.csv`)**: Contains all cleaned, deduplicated tracks available in the dataset, transformed with the training scaler. Using the catalog for recommendations ensures users can discover and search songs without being restricted to an arbitrary 80% train split.

## 🏃 Running the Application

### 1. Set Up Virtual Environment

**Windows (PowerShell):**
```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

**macOS/Linux:**
```bash
python3 -m venv .venv

pip install -r requirements.txt
```

Run the leak-free preprocessing pipeline:
```bash

```

### 3. Launch the Interactive CLI

```bash
python src/main.py
```

## 📊 System Limitations & Future Work

To maintain technical transparency, please note:
1. **Artist TF-IDF**: The artist similarity recommender vectorizes artist name tokens using TF-IDF. It measures **text and collaboration overlap** (e.g., shared featured artists), *not* musical similarity between artists. Developing artist audio-profile embeddings is recommended for a future phase.
2. **Mood Classification**: The mood recommender uses **deterministic rule-based heuristics** based on valence, energy, and tempo thresholds. It is not an ML classifier trained on ground-truth listener mood labels.
3. **Collaborative Filtering**: This system is content-based and hybrid. It relies on track attributes and popularity rather than user-item interaction histories (matrix factorization / collaborative filtering).
